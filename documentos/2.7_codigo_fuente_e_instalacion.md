- **Base del cierre de desarrollo:** `e16c522`

## 1. Qué estoy entregando

CoDataU es una aplicación web para cargar archivos, revisar su calidad, configurar una limpieza y analizar el resultado. Está pensada para personas que trabajan con información, pero que no necesariamente saben programar o construir un proceso de datos desde cero.

En este punto dejo el código y las instrucciones para ponerlo a funcionar. La entrega no depende del entorno de mi computador: las dependencias, las migraciones de la base de datos y los archivos de configuración de ejemplo están en el repositorio.

El alcance corresponde a un MVP funcional, es decir, una primera versión con el recorrido principal completo. No lo presento como un servicio público listo para operar con cualquier volumen de información o cantidad de usuarios.

La entrega de fuentes se puede generar como ZIP con el script incluido. El ZIP lleva una copia del código versionado, estos documentos y un archivo con el commit exacto de la entrega. El historial completo sigue en GitHub; por seguridad y tamaño, la carpeta interna `.git` no se copia dentro del ZIP.

## 3. Qué se necesita

### Para instalar y ejecutar

- Python 3.13 o 3.14, con `pip` y soporte para entornos virtuales. La validación local del cierre se realizó con Python 3.14; el flujo de integración está configurado para ambas versiones.
- Un navegador actualizado.
- Acceso a internet para descargar dependencias. Algunas fuentes, iconos y gráficas también se cargan desde servicios externos.
- Permisos de escritura en la carpeta del proyecto para guardar base de datos y archivos.
- Git, si se va a clonar el repositorio, generar el paquete reproducible o ejecutar la validación completa, que incluye pruebas del empaquetador.
- PowerShell para los scripts `.ps1`. Se pensaron para la instalación en Windows; los comandos equivalentes para otros sistemas aparecen más adelante.

Node.js no es necesario para usar la aplicación. Solo se utiliza para ejecutar las pruebas del formato de las respuestas del chat.

Para una demostración con archivos pequeños, un equipo con 8 GB de RAM es una referencia razonable, no un mínimo certificado por pruebas de carga. El consumo depende del tamaño de los archivos y de los pasos de procesamiento.

### Para las funciones de IA

Se necesita una credencial de API y un modelo habilitado en la cuenta del proveedor. En el desarrollo se utilizó la integración compatible con Google AI Studio. La aplicación también puede iniciarse con la IA desactivada: las reglas locales y la configuración manual no dependen de ella.

## 4. Instalación rápida en Windows

Los comandos se ejecutan desde la carpeta raíz del proyecto, no desde `documentos`.

### 4.1. Obtener el código

Desde GitHub:

```powershell
git clone https://github.com/TheBlackFenix/codatau.git
cd codatau
git switch main
```

Si se recibe el ZIP, basta con descomprimirlo y abrir una terminal en la carpeta `codatau` que contiene `run.py`. Para ejecutar la aplicación desde el ZIP no hace falta inicializar Git.

### 4.2. Preparar la aplicación

```powershell
.\documentos\scripts\instalar.ps1 -ConPruebas
```

El script crea `venv` si no existe, instala las dependencias y crea `.env` únicamente cuando falta. En una instalación nueva genera una clave de sesión aleatoria y deja la IA desactivada. Si ya existe `.env`, no lo sobrescribe ni muestra sus valores.

También ejecuta las migraciones. Esto crea o actualiza la estructura de la base; no carga usuarios de demostración ni archivos de prueba. En una instalación existente hay que respaldar la información antes de actualizar.

Opciones adicionales:

```powershell
# Solo dependencias necesarias para usar la aplicación
.\documentos\scripts\instalar.ps1

# Preparar el entorno sin actualizar todavía la base
.\documentos\scripts\instalar.ps1 -ConPruebas -SinMigraciones

# Elegir un ejecutable de Python cuando hay varias instalaciones
.\documentos\scripts\instalar.ps1 -Python 'C:\Ruta\Python\python.exe' -ConPruebas
```

Si el equipo bloquea scripts por su política de seguridad, se pueden seguir los comandos manuales de la sección 7. No es necesario desactivar de manera permanente las protecciones del sistema.

### 4.3. Iniciar

```powershell
.\documentos\scripts\iniciar.ps1
```

Abrir [http://127.0.0.1:5000](http://127.0.0.1:5000). El servidor queda en esa terminal y se detiene con `Ctrl+C`.

El script solo escucha en el equipo local, desactiva el depurador y no abre túneles. Si el puerto está ocupado, informa el problema sin detener otros procesos. Para usar otro puerto:

```powershell
.\documentos\scripts\iniciar.ps1 -Puerto 5055
```

En ese caso, la dirección es `http://127.0.0.1:5055`.

## 5. Configuración

La configuración privada queda en `.env`, en la raíz. Nunca se debe compartir ese archivo en el repositorio, las capturas o el paquete de entrega. Las variables definidas directamente en el entorno del proceso pueden tener prioridad sobre `.env`.

### Variables principales

| Variable | Para qué sirve |
|---|---|
| `SECRET_KEY` | Firma las sesiones y las confirmaciones. Debe ser propia de la instalación, larga y aleatoria. |
| `DATABASE_URL` | Conexión de la base. `sqlite:///pymes_ai.db` usa la base local en `instance/`. |
| `UPLOAD_FOLDER` | Carpeta de originales. En el ejemplo es `uploads`. |
| `ANALYTICS_FOLDER` | Carpeta de datos procesados y perfiles. En el ejemplo es `artifacts`. |
| `MAX_CONTENT_LENGTH` | Límite de la solicitud de carga en bytes. El valor de ejemplo es 52.428.800, equivalente a 50 MiB. |
| `PROFILE_SAMPLE_SIZE` | Tamaño máximo de la muestra del perfil local. No es la cantidad de filas usadas para calcular métricas. |
| `AI_PROVIDER` | `disabled`, `openai_compatible` u `openai_responses`. |
| `AI_MODEL` | Identificador del modelo predeterminado. |
| `AI_API_KEY` | Credencial privada del proveedor. No se guarda en la base. |
| `AI_BASE_URL` | Dirección base del servicio de IA. |
| `AI_RESPONSE_MODE` | Preferiblemente `json_schema`; existe `json_object` para compatibilidad. |
| `AI_TIMEOUT_SECONDS` | Tiempo máximo de espera por intento. El ejemplo usa 30 segundos. |
| `AI_MAX_OUTPUT_TOKENS` | Presupuesto inicial de salida. El ejemplo usa 1200 tokens. |
| `AI_MODEL_SELECTOR_ENABLED` | `1` muestra el selector de modelos; `0` lo oculta. En desarrollo está habilitado por defecto. |

También se incluyen límites de muestras y candidatos para las tareas de IA. Por defecto, el contexto usa hasta cinco registros y hasta 80 columnas; esto no significa que el proveedor reciba el archivo completo.

Al cambiar `.env` hay que reiniciar el servidor. Elegir otro modelo desde el selector de la aplicación sí afecta las próximas consultas de esa sesión sin reiniciar.

### Ejemplo para Google AI Studio

```dotenv
AI_PROVIDER=openai_compatible
AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
AI_API_KEY=REEMPLAZAR_POR_LA_CLAVE_PRIVADA
AI_MODEL=REEMPLAZAR_POR_UN_MODELO_DISPONIBLE_EN_LA_CUENTA
AI_RESPONSE_MODE=json_schema
AI_MODEL_SELECTOR_ENABLED=1
```

Los valores `REEMPLAZAR_...` son indicaciones, no credenciales ni modelos válidos. El catálogo consulta los modelos de texto que devuelve Google para la cuenta. Su disponibilidad, cuotas y compatibilidad pueden cambiar; no todos los modelos listados están garantizados para todas las tareas de CoDataU.

Cuando el proveedor informa que agotó su límite de salida, se permite un único reintento con un presupuesto adicional acotado. Esto evita ejecutar una respuesta incompleta, pero puede aumentar costo y tiempo. No hay reintentos ilimitados ni cambio silencioso de modelo.

## 6. Verificación de la instalación

### Pruebas locales sin consumir IA

```powershell
.\documentos\scripts\validar.ps1
```

Este script comprueba sintaxis, crea una base de prueba, aplica migraciones, compara el esquema con los modelos y ejecuta las pruebas Python. Si encuentra Node.js, ejecuta además las pruebas JavaScript del chat. Si no lo encuentra, lo informa; no presenta esas pruebas como ejecutadas.

La base y los archivos temporales se ubican en una carpeta nueva dentro de `output/`. No se utiliza la base de trabajo ni se llama a la API. Al terminar se restauran las variables de entorno que cambió el script. Los temporales se dejan para poder revisar el resultado.

### Prueba de uso

1. Abrir la dirección local, registrar una cuenta e iniciar sesión.
2. Cargar un CSV o Excel pequeño con encabezados.
3. Entrar a la limpieza guiada y guardar tipos, duplicados y tratamientos.
4. Revisar la vista previa y confirmar la nueva versión.
5. Descargar el resultado y abrirlo en una hoja de cálculo.
6. Si la IA está configurada, solicitar métricas y hacer una pregunta concreta al chat.

### Pruebas reales con el proveedor

Son opcionales y consumen API. No deben ejecutarse de forma inadvertida:

```powershell
$env:RUN_LIVE_AI_TEST = '1'
try {
    .\venv\Scripts\python.exe -m pytest tests/test_ai_provider_live.py -q --tb=short
} finally {
    Remove-Item Env:RUN_LIVE_AI_TEST -ErrorAction SilentlyContinue
}
```

Estas pruebas usan información sintética. Se necesita una configuración válida de IA. El resultado puede depender de la disponibilidad, cuota y comportamiento del modelo.

## 7. Instalación manual

Sirve cuando no se quieren ejecutar scripts o se necesita revisar cada paso.

### Windows

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

En una instalación nueva, copiar `.env.example` como `.env` y sustituir la clave de sesión por una aleatoria. Si `.env` ya existe, conservarlo y revisarlo; no reemplazarlo con la plantilla. Después:

```powershell
.\venv\Scripts\python.exe -m flask --app run db upgrade
.\venv\Scripts\python.exe -m flask --app run --no-debug run --host 127.0.0.1 --port 5000 --no-debugger --no-reload
```

### Linux o macOS

```bash
python3 -m venv venv
./venv/bin/python -m pip install -r requirements-dev.txt
```

Crear `.env` a partir de la plantilla, sin sobrescribir una configuración existente, y asignar una clave de sesión propia. Luego:

```bash
./venv/bin/python -m flask --app run db upgrade
./venv/bin/python -m flask --app run --no-debug run --host 127.0.0.1 --port 5000 --no-debugger --no-reload
```

Los comandos corresponden al proyecto, pero esta entrega no certifica un despliegue manual en cada distribución o versión de macOS. El trabajo local se verificó en Windows y el flujo automatizado está definido para Linux en GitHub.

## 8. Generar el archivo comprimido de entrega

Primero, guardar los cambios que se van a entregar en Git. El empaquetador rechaza cambios versionados sin commit para evitar que el documento y el ZIP correspondan a versiones distintas.

```powershell
.\venv\Scripts\python.exe documentos/scripts/empaquetar.py --referencia main
```

El comando crea un ZIP nuevo en `output/entregas/`, junto con un archivo `.sha256`. También se puede indicar un destino:

```powershell
.\venv\Scripts\python.exe documentos/scripts/empaquetar.py --referencia main --destino output/entregas/codatau-entrega-final.zip
```

El script toma únicamente el contenido guardado en la referencia de Git elegida. No recorre ni empaqueta las carpetas personales del equipo. Revisa nombres de archivos para impedir incluir configuraciones privadas, bases locales o artefactos de usuarios que se hubieran versionado por error. Esta comprobación no reemplaza una revisión de secretos escritos dentro del código.

El ZIP incluye `ENTREGA.txt` con el repositorio, el commit y la fecha de generación. No incluye el historial completo ni un respaldo de la instalación. Tampoco sobrescribe un paquete existente.

Para comprobar que el archivo recibido coincide con el generado:

```powershell
Get-FileHash output/entregas/codatau-entrega-final.zip -Algorithm SHA256
```

Comparar el valor con el archivo `.sha256`. Esta comprobación detecta cambios en el paquete; no sustituye la verificación de quién lo entregó.

## 9. Actualizar, respaldar y detener

Antes de actualizar una instalación con información:

1. Detener CoDataU con `Ctrl+C` en la terminal que lo ejecuta.
2. Copiar la base de `instance/`, los originales de `uploads/` y los procesados de `artifacts/`. Si se configuraron otras rutas, respaldar esas rutas. La copia debe corresponder al mismo momento.
3. Guardar `.env` aparte, en un lugar privado. No incluirlo en el ZIP académico ni en GitHub.
4. Obtener los cambios de `main` y actualizar dependencias.
5. Ejecutar `db upgrade`, validar y volver a iniciar.

No se debe borrar la base para actualizar el proyecto. Las migraciones existen precisamente para cambiar su estructura conservando la información. Restaurar una copia de seguridad tampoco consiste en copiar solo la base: los archivos y las versiones deben seguir disponibles.

## 10. Problemas frecuentes

| Situación | Qué revisar |
|---|---|
| El puerto ya está ocupado | Detener la instancia anterior desde su terminal o usar otro puerto. No cerrar procesos que no se hayan identificado. |
| Aparece que falta una tabla | Ejecutar las migraciones en la instalación y con el entorno correctos. |
| Falla la instalación de una dependencia | Revisar la versión de Python, la conexión y que se esté utilizando el entorno virtual. |
| Windows rechaza archivos temporales con rutas largas | Instalar en una ruta corta. El script de validación usa nombres temporales cortos para reducir este problema. |
| El proveedor rechaza una consulta | Revisar la clave, la cuota, el modelo y la dirección del servicio, sin publicar la credencial. |
| El modelo entrega una respuesta incompleta | Esperar el reintento acotado; si falla, probar una pregunta más sencilla o un modelo compatible más ligero. |
| El navegador muestra una sesión inválida | Recargar o volver a iniciar sesión. Cambiar `SECRET_KEY` invalida sesiones y confirmaciones pendientes. |
| No se ven iconos o gráficas | Revisar conexión y bloqueos a los recursos externos del navegador. |

## 11. Qué no cubre este despliegue

El servidor usado aquí es el de desarrollo de Flask, aunque se ejecute sin depurador. Sirve para evaluación local; no se debe publicar tal cual en internet. Una instalación pública requiere un servidor de aplicación adecuado, HTTPS, configuración de seguridad, copias programadas, cuotas, supervisión y pruebas de carga.

No se entrega una imagen Docker, un instalador de escritorio ni una infraestructura en la nube. Las instrucciones anteriores corresponden al despliegue local real del MVP. El funcionamiento de la aplicación se explica en el [manual de usuario](2.8_manual_de_usuario.md), y sus decisiones y limitaciones se desarrollan en el [informe técnico](2.9_informe_tecnico.md).
